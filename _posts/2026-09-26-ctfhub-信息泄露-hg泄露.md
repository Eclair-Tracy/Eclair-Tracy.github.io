# 【CTFHub】Web-HG泄露 Writeup

## 一、漏洞简述
Mercurial（简称 Hg）是一种版本控制工具。当开发人员使用 Mercurial 进行版本控制，且配置不当时，可能会将 `.hg` 文件夹直接部署到线上环境。攻击者可以通过访问 `.hg/store/` 目录下的相关文件，还原源代码、文件列表甚至获取未提交的敏感文件，这就是 HG 泄露漏洞。

## 第一步：确认漏洞存在
访问靶场根目录，尝试探测常见路径：
`http://challenge-xxx.sandbox.ctfhub.com:10800/.hg/`

如果页面返回相关的版本信息或目录结构，即可确认漏洞存在。直接访问 `flag.txt` 或 `flag.txt.i` 等常规路径通常会返回 404 Not Found。

## 第二步：下载核心历史数据文件
手工下载以下两个关键索引文件到本地：
*   `/.hg/store/00manifest.i` （记录文件清单）
*   `/.hg/store/00changelog.i` （记录提交日志）

此时，若直接访问 `/.hg/store/data/flag.txt.i` 等路径，依然返回 404，说明还需要进行底层数据解析。

## 第三步：Python 手工解压与初次线索挖掘
Mercurial 的 `.i` 文件包含 64 字节的索引头，后面跟着 Zlib 压缩数据。由于浏览器版 CyberChef 在处理二进制文件时容易出错，本次采用 **Python 脚本**进行手工解压（等价于 CyberChef 的 `Drop bytes (64) -> Zlib Inflate` 配方）：

python
import zlib

# 解压 manifest
try:
    with open('00manifest.i', 'rb') as f:
        f.read(64) # 丢弃前64字节头部
        data = f.read()
    print("=== 00manifest.i 的内容 ===")
    print(zlib.decompress(data).decode('utf-8', errors='ignore'))
except Exception as e:
    print("manifest解压失败:", e)

# 解压 changelog
try:
    with open('00changelog.i', 'rb') as f:
        f.read(64)
        data = f.read()
    print("\n=== 00changelog.i 的内容 ===")
    print(zlib.decompress(data).decode('utf-8', errors='ignore'))
except Exception as e:
    print("changelog解压失败:", e)

# 解压结果：
解压后，发现 00changelog.i 中记录了 50x.html、index.html 和 init 等提交记录，但这两个文件中均未包含 flag 相关的文件名。这说明 flag 文件可能处于未提交状态，或者没有被记录在当前 manifest 索引中。
 
## 第四步：深入挖掘 fncache 文件（关键突破）
 
既然常规索引文件没有线索，转而下载 .hg/store/fncache 文件。这个文件记录了所有被跟踪过的文件名（包括未提交的文件）。
 
使用 cmd 中的 curl 命令快速获取：
curl http://challenge-xxx.sandbox.ctfhub.com:10800/.hg/store/fncache
 
终端回显如下：
data/index.html.i
data/50x.html.i
data/flag_482810223.txt.i
 
成功发现了一个未提交的隐藏文件：data/flag_482810223.txt.i。
 
## 第五步：访问根目录获取 Flag（成功）
 
在 Mercurial 中，.i 结尾的文件是索引文件，真正的文本内容应当去掉 .i 后缀。获取到文件名后，直接拼接 URL 访问靶场根目录：
 
http://challenge-xxx.sandbox.ctfhub.com:10800/flag_482810223.txt
 
浏览器成功回显 Flag{...}，解题完成。

## Flag
ctfhub{32e6297c8d2d8883efd996c3}
 
## 总结与经验
1. 不要局限于常规解压：当 00manifest.i 和 00changelog.i 中没有有效信息时，一定要想到 fncache 文件。它经常能暴露出开发人员忘记提交（或者故意隐藏）的敏感文件。
2. 工具选择：处理二进制解压时，Python 脚本比网页版前端工具（如 CyberChef）更稳定高效。
3. URL 拼接技巧：拿到文件名后，去掉版本控制的 .i 扩展名，直接去根目录访问实际文件即可拿到最终结果。
